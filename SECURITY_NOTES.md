# SQL ID Library Security Notes

## What this library does

This library maps a positive SQL integer ID to a public hex handle and back again:

```text
SQL integer -> layout pack -> secret-keyed Feistel permutation -> lowercase hex
```

The plaintext packed value is:

```text
[ version ][ zero-based SQL id index ][ keyed validation tag ]
```

It hides sequential IDs and rejects almost all random or tampered strings. It is not an authorization layer and not a bearer-token system.

## Fixed layout registry

The encoder uses a named profile plus `boosted=False/True`. The decoder uses public hex length only. No caller supplies arbitrary bit counts.

## Secret and domain separation

`XCTX_ID_PASSWORD` must be at least 32 UTF-8 bytes and should be generated by the OS CSPRNG:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

The HMAC key schedule includes the layout identity:

```text
scheme revision
profile
mode
version bits
id bits
tag bits
total bits
hex chars
issue version
```

This prevents tags or Feistel keys from one profile/mode from being meaningful in another profile/mode.

## Random guessing profile

For any layout:

```text
valid public IDs = 2^id_bits - 1
public space     = 2^total_bits
random-valid p   = (2^id_bits - 1) / 2^total_bits
```

Normal mode:

```text
4 version bits + 28 tag bits = 32 rejection bits
p < 2^-32
```

Boosted mode:

```text
minimum: 4 version bits + 60 tag bits = 64 rejection bits
p < 2^-64
```

Boosted `uint24` and `uint32` have 76 tag bits, so their random-valid probability is under `2^-80`.

## Rate-limit hardening

A deployment can make online guessing impractical by treating bad public IDs as suspicious. Suggested policy:

```text
10 bad public IDs per session/IP/account bucket per 30 minutes,
then a 30-minute block or challenge.
```

This caps guesses to:

```text
10 * 2 * 24 * 365 = 175,200 guesses/year/bucket
```

Normal mode expected time to hit any syntactically valid public ID:

```text
2^32 / 175,200 ~= 24,515 years/bucket
```

Least-rejecting boosted mode expected time:

```text
2^64 / 175,200 ~= 105,289,635,123,913 years/bucket
```

If the attacker must hit a real row, use:

```text
expected guesses ~= 2^total_bits / live_row_count
```

for the selected layout.

## Intended use

Suitable:

- compact public SQL-ID camouflage
- internal public handles
- deterministic row handles where normal authorization is still checked

Not suitable:

- bearer tokens
- reset links
- magic-login links
- invite tokens
- download grants
- API keys
- sessions

For bearer-token uses, generate independent random tokens of at least 128 bits.

## Operational notes

- Generation returns lowercase hex.
- Decoding accepts uppercase or lowercase hex.
- `id_to_hex()` and `hex_to_id()` return `None` on failure.
- `validate_hex()` returns a structured error result.
- ID `0` is always invalid.
- For profile `uintN`, accepted IDs are `1..(2^N - 1)`.
- The raw all-ones ID-index state is rejected for every profile.
